# Hardware and wiring

Target: NVIDIA Jetson Orin Nano (developer kit carrier board). All GPIO code uses `Jetson.GPIO` in `GPIO.BOARD` mode, so pin numbers below are **physical pins on the 40-pin header**.

### Discrepancies you should resolve against the physical wiring

1. The README's old pinout listed servos on 21, 23, 27, 29 and the hand stepper on 13, 15, 16. The code uses servos on 21, 23, 24, 37 and the gripper STEP on 32 (the Arduino firmware header in `arm_controller/firmware/arm_stepper_arduino/` also says pin 32). The README has been updated to match the code, but the code could be the stale side — check the harness.
2. Pin 37 (servo 2 right) is not in the device-tree overlay, and pin 15 is in the overlay but unused by the current driver. Pins that are not muxed to GPIO by the overlay may not be driveable.
3. `jetson_morse.cpp` / `pwmtest.cpp` drive a Morse key servo with sysfs PWM on pin 32 (`/sys/class/pwm/pwmchip3/pwm0`). The gripper STEP also uses pin 32. They cannot both be in use.

## Stepper drivers (DM556Y)

Two drivers, selectable at runtime:

- **Direct GPIO** (`arm_stepper_driver`): the Jetson sets DIR and a trigger level on STEP; the pulse train itself is generated by an Arduino acting as a slave step generator.
- **Arduino serial** (`arm_stepper_arduino_driver`): the Jetson sends `M <arm_dir> <arm_freq> <grip_dir> <grip_freq>\n` over `/dev/ttyACM0` at 115200 baud (and `S\n` to stop, `PING\n` to handshake) and the Arduino produces the step pulses. A command is re-sent at least every 100 ms as a watchdog heartbeat.

Firmware: [`ros2_ws/src/arm_controller/firmware/arm_stepper_arduino/`](../ros2_ws/src/arm_controller/firmware/arm_stepper_arduino/arm_stepper_arduino.ino). Step/frequency math is in [arm-and-kinematics.md](arm-and-kinematics.md).

## Motor controllers (VESC over CAN)

- Jetson CAN0 on connector J17; enabled by [`can0_overlay.dts`](../can0_overlay.dts) (pin-mux registers `0x0c303018` RX and `0x0c303010` TX, `mttcan0` enabled).
- Bring-up: `sudo ip link set can0 type can bitrate 500000 restart-ms 100`, then `sudo ip link set up can0`.
- Default wheel CAN IDs (`vesc_can_driver_node` parameters): front-left 53, front-right 44, rear-left 48, rear-right 7. `dashboard_helper` launches the driver with its own ID list; keep the two in step.
- Compile the overlays with `dtc -@ -I dts -O dtb -o <name>.dtbo <name>.dts`. The `.dtbo` binaries are no longer tracked (they are in `.gitignore`).

## Serial devices

| Device | Default port | Baud | Used by |
|---|---|---|---|
| GNSS receiver | `/dev/ttyUSB0` | 38400 | `gps_bridge_node.py` **and** `NAVnode` (parameter `gnss_port`) |
| Morse/XLR Arduino | `/dev/ttyUSB0` | 115200 | `morse_bridge_node` |
| Arm stepper Arduino | `/dev/ttyACM0` | 115200 | `arm_stepper_arduino_driver` |

Several nodes default to the same `/dev/ttyUSB0`. Only one process can own a port at a time, so assign stable names (udev rules) or pass `port` parameters explicitly. In particular, `gps_bridge_node` and `NAVnode` cannot both read the GNSS receiver.

## Cameras

CSI cameras 0 and 1 (sensor IDs; focus motors on I²C buses 10 and 9, address `0x0c`) and a USB camera at `/dev/video2`. The process manager streams them over UDP to the base station on ports 5000, 5002 and 5004; see [mission-tasks.md](mission-tasks.md).

## Network

| Address | Role |
|---|---|
| `192.168.1.87` | Base station/operator (video target and FastDDS peer) |
| `192.168.1.88` | Second FastDDS peer |
| `127.0.0.1` | Local discovery on the Jetson |

`fastdds_profiles.xml` disables the built-in transports (avoiding SHM lockups), uses UDPv4 with 1 MB socket buffers and a 65500-byte message size, and configures hybrid multicast (`239.255.0.1`) plus the three static peers above (`127.0.0.1`, `192.168.1.87`, `192.168.1.88`). Check multicast load on the antenna link when running field hardware. The `video_streamer.py` default host is `192.168.1.10`, which does not match; the process manager passes `--host 192.168.1.87` explicitly.

## Physical dimensions (`rover_description/config/physical_params.yaml`)

Chassis 0.70 × 0.50 × 0.20 m, 15 kg; four wheels of radius 0.15 m, 1.5 kg each; arm column base offset 0.10 m, column height 0.40 m, mount length 0.30 m, arm length 0.45 m, tool tip 0.15 m. Both `vesc_can_driver_node` and `rover_ekf` now load `wheel_radius` (`0.15 m`) from this YAML; measure physical tires outdoors before field runs — see [known-issues.md](known-issues.md).
